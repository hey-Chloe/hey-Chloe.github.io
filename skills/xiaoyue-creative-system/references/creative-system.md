# XIAOYUE 创意系统

版本：0.4 / 2026-09-07  
定位：一个能够同时容纳产品、系统、模型、个人档案与研究过程的长期视觉与叙事系统。

## 1. 北极星

**XIAOYUE 是一份持续生长的索引，收录做过、测试过和学到的事物。**

中文语义：小悦的数字世界不是一份简历，而是一套仍在生长的索引。它保存作品，也保存作品如何形成；保存结论，也保存实验边界。

审美北极星：**柔软档案 × 好玩交互 × Apple 级精致度 × 严肃 AI 作品**。

翻译为体验：看起来是小悦自己的数字收藏室；摸起来像真实物件一样好玩；动起来精致、克制、有物理连续性；点进去以后，作品和证据负责证明技术实力。严肃来自内容，不来自尖角、巨型英文或研究出版物姿态。

默认品牌行：

```text
小悦
XIAOYUE

PRODUCTS
SYSTEMS
MODELS
```

`®` 是视觉语气，不代表法律上的注册声明。若无真实注册，应改成 `XIAOYUE /` 或 `XIAOYUE INDEX`，避免误导。

### 身份四层模型

从稳定到可变依次为：

1. **稳定价值**：中文优先、证据诚实、保留成长过程、好玩但可用。
2. **世界语法**：Archive 收纳与打开，Work 展开与演示，Lab 检查与追溯。
3. **项目专属表达**：由真实产品、算法、数据、人物或媒介决定的构图和交互。
4. **可替换表皮**：绿色、纸纹、石材、花、Mono、手写字、圆角、贴纸与阴影。

更新设计时优先保住前两层，并让第三层承担差异化；第四层可随用户明确选择调整。禁止把第四层固化成全站必须出现的套装。

`XIAOYUE` 是跨 Archive、Work、Lab、Notes 的总身份；`Chloe’s Archive` 只承担 Archive 的英文字标角色。

## 2. 三个世界，一个身份

### WORLD A — ARCHIVE

负责“我是谁、我如何生长”。

- 内容：首页身份、关于（About）、笔记（Notes）、花园（Garden）、阅读（Reading）、速写本（Sketchbook）、个人实验。
- 情绪：温暖、有触感、柔软、好玩、私人；不是尖锐的编辑式风格。
- 材料：圆角纸张、索引标签、透明套、照片、批注、植物碎片。
- 构图：叠纸、层级遮挡、非对称、明显留白；对象可被拖动、重排、展开和点击进入。
- 标志性交互（Signature Interaction）：用户看到散落档案就应本能地拖动和打开；不依赖说明文字才能理解玩法。
- 禁止：建筑事务所式硬网格、儿童贴纸墙、同款胶囊卡片矩阵、每处都有花、占据主视觉的操作说明。

### WORLD B — WORK

负责“作品自己证明能力”。

- 内容：产品、Agent、AI 应用、生成式媒体、交互演示、案例研究。
- 情绪：聚焦、精致、自信、由媒体主导，但仍保留小悦的柔和物件 DNA。
- 材料：从 Archive 纸张展开出的真实 UI、屏幕录制、产品输出、系统剖面、关键媒体。
- 构图：一个强视觉中心；项目可拥有独立艺术方向。
- 叙事：中文负责讲清故事，英文只负责真实技术标签；问题 → 输入 → 系统 → 过程 → 输出 → 证据。
- 入口与动作：按钮、链接、状态说明和操作提示默认使用自然中文；英文仅限不可替代的技术名词、正式产品名或极轻 metadata，不用装饰性英文制造高级感。
- 禁止：每个项目都套同一张卡、只有技术栈、没有真实输出、照搬 Apple。

### WORLD C — LAB

负责“方法、实验和边界”。

- 内容：LLM、Agent、RAG、模型、训练、评估、Benchmark、论文复现、算法。
- 情绪：精确、清晰、实验性、诚实，但像“小悦的实验桌”而不是黑白学术海报。
- 材料：圆角实验纸、追踪记录、终端、数据集表格、曲线图、Prompt、批注、失败记录。
- 构图：实验材料铺在桌面上；允许轻叠层和少量手写边注，但数据层必须严谨。
- 叙事：问题 → 基线 → 方法 → 运行 → 指标 → 失败 → 下一次实验。
- 禁止：普通 ML 仪表盘、无数据的科技线条、用图表形状冒充真实结果。

## 3. 统一身份锚点

三个世界不靠 Logo 统一，也不按配额凑符号。根据页面内容从以下锚点中选择 2–4 项；中文叙事、真实性边界与状态连续性始终保留。连续页面不要机械复用完全相同的组合。

1. **档案编号（Folio）**
   - 格式：`A.01` Archive、`W.01` Work、`L.01` Lab。
   - 用于页码、实验号、作品号、导航状态和转场。

2. **Bloom 标记**
   - 一朵由 6 个叶片 / 花瓣构成的小型标记。
   - Archive 可表现为印刷或手绘；Work 为极简切口；Lab 为六节点结构。
   - 一屏最多出现一次显著 Bloom。

3. **索引脊线**
   - 桌面为左侧或顶部的稳定细线 / 标尺，移动端为顶部档案编号栏（folio rail）。
   - 承载所属世界、章节、年份和证据状态。

4. **媒体说明**
   - 所有媒体有名称、角色、状态和来源。
   - 示例：`OUTPUT 03 / RETRIEVAL EVALUATION / REPOSITORY REPORTED / 2026-08-14`。

5. **转场短语**
   - Archive：`OPEN FILE`
   - Work：`ENTER PRODUCT`
   - Lab：`INSPECT RUN`
   - 语言不同，但语法统一为动词 + 对象。

6. **柔和曲线**
   - 圆角是基础形状语言，用于纸张、媒体窗口、实验材料和 hover / focus 状态。
   - 圆角表达柔软物件感，不等于把所有内容做成同款胶囊卡片。

7. **Archive 字标与交互**
   - `Chloe’s Archive` 手写字标、叠纸、拖拽与层级遮挡是长期品牌资产。
   - Work 可把纸张展开成产品舞台；Lab 可把纸张转译成实验材料，但不能彻底抹除这套 DNA。

## 4. 字体系统

### 4.1 角色而不是单一字体

```text
现代无衬线（Modern Sans）  — 主界面、中文标题、中文叙事、产品界面
展示衬线（Display Serif）  — Notes 文章标题、研究引用、偶发编辑式时刻
等宽字体（Mono）           — 档案编号、参数、追踪记录、证据、实验编号
手写字体（Handwritten）    — Chloe’s Archive 品牌字标与极少量边注
```

### 4.2 建议字体栈

原型可使用系统字体；发布版本应选择有稳定 Web 字体文件和许可的组合。

```css
--font-serif: "Newsreader", "Iowan Old Style", "Noto Serif SC", "Songti SC", serif;
--font-sans: "Inter", "Noto Sans SC", "PingFang SC", "Microsoft YaHei", sans-serif;
--font-mono: "IBM Plex Mono", "SFMono-Regular", "Cascadia Code", monospace;
--font-signature: "Kaushan Script", cursive;
```

- 正式发布使用 `Kaushan Script Regular 400` 的 Google Fonts 官方 v19 Latin WOFF2，站内自托管，不再依赖系统手写字体栈。
- 授权为 SIL Open Font License 1.1；字体文件旁保留 `OFL.txt` 与 `METADATA.pb`，仓库根目录保留 `THIRD_PARTY_NOTICES.md`。
- `Kaushan Script` 是保留字体名（Reserved Font Name）。当前 WOFF2 未修改；不得在本地制作子集、重建或改绘后继续沿用该字体名。
- 正式字标固定写作 `Chloe’s Archive`（U+2019 弯引号），统一通过 `ChloesArchiveWordmark` 组件使用。
- 这是明确授权的品牌字标实现，不宣称字体归 Chloe 所有。字体只用于英文字标；中文界面继续使用现代 Sans。
- 中文界面标题与正文默认柔和现代 Sans，字重避免过黑；Archive 长文或 Notes 标题才可偶发 Serif。
- 不用“宋体高级”作为默认判断，不让巨型宋体统治首页 / Archive / Work / Lab。
- 中英标题可以同一基线混排，不把中文缩成英文的附属翻译。

### 4.3 字号层级

```text
Display XL  clamp(4.5rem, 12vw, 10rem)  / 0.88–0.96
Display L   clamp(3rem, 7vw, 6.5rem)    / 0.94–1.02
Heading M   clamp(2rem, 4vw, 3.75rem)   / 1.02–1.12
Body L      clamp(1.125rem, 1.4vw, 1.35rem) / 1.65–1.85
Body        1rem–1.125rem / 1.7–1.9 for Chinese
Label       0.68rem–0.78rem / 1.25, Mono, letter-spacing 0.08–0.14em
```

## 5. 色彩系统

### 可用身份色

```text
Ink          #101512  墨色；比纯黑更温暖
Paper        #F1EBDD  温暖档案纸
Paper Cool   #D9DDCF  透明套 / 安静面板
Moss         #244A31  Archive 主场颜色
Moss Light   #76906F  有生命力的辅助色
Bloom        #F06F52  来自 GitHub Profile 的身份强调色
Bloom Soft   #F4B69F  轻量批注色
Signal Lime  #C9F36A  只用于 Lab 执行状态，不作装饰
```

### 使用原则

- Archive：根据当次已批准的空间底材决定大面积颜色；Moss、Paper 和 Bloom 作为可选身份线索，不按固定比例强制出现。
- Work：项目媒体决定主色；核心身份色只出现在档案编号、说明或转场。
- Lab：Ink / Paper Cool 85%，Signal Lime 只标执行状态，Bloom 只标人的注释。
- 不使用蓝紫 AI 渐变作为默认状态。

### 对比度

- 正文与背景至少满足 WCAG AA。
- Signal Lime 不承担大段文字。
- 半透明纸张下仍必须有独立可读底色；不能只靠背景模糊保证对比。

## 6. 间距原则

以 `4px` 为最小单位，但不做平均网格。

```text
4 / 8     微小细节
12 / 16   标签、控件、说明
24 / 32   组件内部
48 / 64   章节节奏
96 / 128  世界转场
160+      电影感呼吸空间
```

规则：

- 信息密度来自内容关系，不来自把所有东西缩小。
- 每个高密度区域前后必须有低密度缓冲。
- 叠层最多 3 个主要平面；更多层只允许作为短暂动态状态。
- 中文正文行宽约 28–42 个汉字；研究表格例外。

### 柔和形状语言

- 基础曲率按对象尺寸分级：小标签 8–12px，纸张与实验材料 18–28px，大型媒体窗口 28–48px。
- 纸张可有不完全一致的曲率、轻微旋转、阴影和遮挡；不要复制一套统一 SaaS 卡片。
- 悬停 / 聚焦（hover / focus）表现为轻抬、露出页边、层级前移或边缘发光，不用夸张弹跳。
- 尖角只保留给真实数据表、终端或需要精确对齐的技术区域，并作为局部对比而非全站语言。

## 7. 构图语言

### Archive

- 桌面是可玩的档案场：叠纸 + 可拖动 + 可点击 + 层级遮挡。
- 纸张不是卡片矩阵：使用圆角、页边、装订、透明套、索引耳和边注制造材料差异。
- 同一屏只有一件主档案处于激活状态；被拖动对象自然升到顶层。
- 最多在首次靠近时出现极轻的 `DRAG / OPEN`；重置功能藏在小型溢出菜单中，不占主视觉。

### Work

- 纸张展开为项目舞台；主视觉媒体占首屏 55–85%，标题不压住关键 UI。
- 中文先说明项目价值，英文只标注真实技术组件。
- 交替使用满版媒体、左右分栏证据、吸附媒体，同一结构不要连续重复超过两章。
- 一项真实输出优先于四张抽象系统图。

### Lab

- 实验材料铺在柔和桌面上，可使用局部对齐线但不让 12 列硬网格统治视觉。
- 数据、方法、结论分层；图表不使用装饰轴。
- 失败案例与成功指标同等级展示。

## 8. 组件语法

### 全局组件

- `WorldRail`：所属世界、档案编号、年份、当前章节。
- `BloomMark`：身份签名。
- `EvidenceLabel`：`VERIFIED / REPOSITORY REPORTED / PROTOTYPE / WIP`。
- `MediaCaption`：类型、来源、时间、版权 / 生成说明。
- `WorldPortal`：从 Archive 进入 Work / Lab 的过渡对象。

### Archive 组件

- `ArchiveDesk`、`ArchiveSheet`、`IndexTab`、`PhotoSleeve`、`Marginalia`、`ObjectDrawer`、`OverflowReset`。

### Work 组件

- `ProductStage`、`ScreenFilm`、`OutputCompare`、`StickyChapter`、`SystemCutaway`。

### Lab 组件

- `ExperimentDesk`、`ExperimentSheet`、`RunTrace`、`MetricTable`、`FailureNote`、`DatasetCard`、`AblationPlot`。

任何组件只有在真实内容需要它时才出现；组件名不是强制页面模板。

## 9. 动态语言

### 统一物理感

- 进入：内容由“被收纳”变成“可检查”。
- 离开：对象回到其所属世界的容器，而非任意淡出。
- 默认缓动：`cubic-bezier(.2,.72,.2,1)`；微交互 160–260ms，章节转场 500–900ms。
- 所有主要动态都必须有 reduced-motion 替代。

### Archive 动态

- 拖动纸张时抬升层级、保留抓取偏移、释放时柔和落桌；点击未发生拖动时才打开。
- 抽卡、翻页、展开折页、移动透明片、扫描线短暂经过。
- 不用大段说明代替可操作暗示（affordance）；优先通过露出的页边、光标和层级反馈让玩法自解释。
- 视差幅度小于 24px；不做漂浮贴纸。

### Work 动态

- 媒体展开、遮罩揭示、镜头推进、UI → 输出转场、滚动控制影片。
- 动态负责解释输入、系统和输出之间的关系。

### Lab 动态

- 追踪节点按真实顺序激活；指标更新显示运行编号和状态。
- 图线绘制必须对应真实数据，不为装饰循环。

### 禁止

- 全站统一 `fadeIn + translateY`。
- 光标尾迹、粒子、随机磁吸成为主要视觉。
- 自动播放有声视频。

## 10. 证据与真实性协议

每个作品或实验声明属于以下一类：

```text
VERIFIED             本次或当前发布流程实际运行并保留产物
REPOSITORY REPORTED  仓库内有报告 / 命令 / 数据，但本次未复跑
PROTOTYPE            可交互原型或视觉重建，不代表生产数据
WIP                  尚未完成或尚未评估
```

任何数字旁至少包含：

- 指标（metric）名称与方向；
- 数据集 / 样本；
- 运行日期；
- 环境；
- 来源产物；
- 是否由本次复跑。

不允许只有“大数字 + 百分号”。

## 11. 媒体需求协议

如果没有真实媒体就无法达到质量门槛，停止该区域的视觉定稿，并输出：

```text
MEDIA REQUEST / 媒体需求
类型：
用途：
位置：
宽高比：
建议尺寸：
必需来源 / 参考：
采集或生成方式：
验收标准：
```

优先顺序：

1. 真实产品截图 / 屏幕录制；
2. 真实模型输出 / 数据可视化；
3. Web 动态；
4. 动态图形；
5. AI 生成媒体；
6. 不使用随机图库素材或廉价渐变代替缺失证据。

## 12. 视频决策规则

视频不是默认高级感。

- UI 交互可重现：优先真实屏幕录制。
- 几何 / 数据 / 节点转场：优先 Web 动态。
- 需要材质、摄影、不可实时生成的镜头：考虑动态摄影或 AI 视频。
- AI 视频需要稳定主体或产品 UI 时，必须先提供参考图 / 首帧 / 尾帧。
- 所有网页视频提供封面图、移动端降级方案、reduced-motion 降级方案，并遵守性能预算。

详细生产流程由 `xiaoyue-video-director` Skill 负责。

## 13. 响应式系统

- 移动端不是桌面叠层的缩小版。
- Archive 由自由摆放转为纵向索引托盘；保留轻微重叠但保证触控和阅读。
- Work 取消复杂横向镜头移动，保留媒体与章节关系。
- Lab 表格允许横向滚动，但结论、运行状态和失败信息不能被藏在悬停状态中。
- 最小触控目标 44 × 44px；焦点状态不可只靠颜色。

## 14. 性能预算

目标而非虚假保证：

- 首屏关键媒体只加载 1 个。
- 初始状态优先加载视频封面；视频进入相邻视口时再加载。
- 单个 WebM 首屏视频建议控制在 4–6 MB 内；移动端使用更低码率或静态降级方案。
- 不让装饰元素成为 LCP。
- 避免固定全屏纹理持续重绘。
- 页面动态在中端移动设备上保持流畅；复杂效果必须可降级。

## 15. 命名系统

```text
XIAOYUE INDEX      全站
ARCHIVE A.01       个人与知识档案
WORK W.01          产品与系统作品
LAB L.01           模型、算法与实验
NOTE N.001         长文 / 学习记录
RUN R.20260823.01  实验或评测运行
OUTPUT O.01        可检查的结果媒体
```

标题写具体对象，不写空洞宣言。例如：

- 好：`A coding agent that can stop, ask, and resume.`（一个会停止、询问并继续执行的 Coding Agent。）
- 好：`10,368 retrieval questions, with the run attached.`（10,368 个检索问题，并附完整运行记录。）
- 差：`Building the future with AI.`（用 AI 建设未来。）

## 16. 质量门槛

每次发布前回答：

1. 删除 XIAOYUE 名字后，中文叙事、物件语义、世界反差与证据连续性是否仍能指向同一个人？
2. 页面是否像 Vercel、Framer 或 AI SaaS 模板？若是，继续修改。
3. 作品是否通过真实 UI、输出、追踪记录或报告证明，而非自我描述？
4. 缺失媒体是否触发了 `MEDIA REQUEST`，而不是被假素材掩盖？
5. 中文是否具有独立的字重、行距、换行和标点处理？
6. 动态是否解释关系？关闭动态后内容是否仍完整？
7. 桌面与移动端是否都可用？

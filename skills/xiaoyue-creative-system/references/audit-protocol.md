# 视觉审计协议

开始设计前，先以足够辨识细节的分辨率检查用户提供的每张图片。对每张图片记录：字体、颜色、构图、间距、纹理、材料、密度、动态潜力、个性、信息层级、个人身份信号、可转移原则，以及不可复制的项目专属元素。

对于现有网站，同时检查源代码与实际渲染结果。记录哪些内容具有辨识度、哪些显得通用或廉价、哪些会破坏信任、哪些交互必须保留，以及哪些声明缺少证据。

最后总结所有参考中共同的审美基底。不要把某一张截图当成完整答案。

## 差异化审计

用户要求差异化时，为每个主要决定标记来源：

- `PERSONAL EVIDENCE`：真实经历、项目、照片、文字、失败或用户反复确认的选择。
- `PROJECT LOGIC`：由当前产品、算法、数据或交互任务决定。
- `EXTERNAL REFERENCE`：从外部案例吸收的可转译原则。
- `SURFACE STYLING`：颜色、纹理、字体、阴影等可替换表皮。

优先保留前两类。外部参考不能压过个人证据；表皮不能被误判为品牌内核。

必须执行四个测试：

1. **去标识测试**：移除名字与 Logo，是否仍能从内容与行为认出 XIAOYUE？
2. **去表皮测试**：移除绿色、纸纹、花与手写字，核心体验是否仍成立？
3. **换项目测试**：换成任何人的项目后是否无需改变构图？若是，仍然模板化。
4. **物件理由测试**：每个主要物件能否说明形状、位置、动作与真实目的地的理由？

审计输出至少包含：`稳定身份 / 常见表达 / 项目专属机制 / 应删除的噱头 / 下一步验证`。不要用“更高级”“更有氛围”代替判断。
